# Spec-driven development в этом магазине

Сначала фиксируем **поведение** в спецификации, потом пишем тесты по её примерам, и только затем код. Код не спорит со спекой: если поведение меняется — сначала меняется `spec.md`.

## Цикл

1. Описать фичу в `specs/NNN-slug/spec.md` (цель, сценарии, таблица примеров).
2. Если нужно — набросать `plan.md` (файлы, ограничения) и `tasks.md`.
3. Перенести примеры из спеки в unit-тесты **до** реализации.
4. Реализовать ровно то, что в спеке.
5. Прогнать тесты. Расхождение — баг в коде или ошибка в спеке; правим источник правды и код вместе.

Спека остаётся в git, пока правило живое. Снятое поведение не оставляем актуальным текстом: либо `status: снято`, либо новая папка с тем же номером/следующим, которая явно сменяет предыдущую.

## Новая фича

Скопируйте папку примера, замените сценарии и таблицу. Не пишите в спеке «как устроено Vue» — только что должен увидеть покупатель и какие данные на входе/выходе.
