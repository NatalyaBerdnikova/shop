# Сортировка каталога

Статус: реализовано  
Страница: `/catalog`

## Зачем

Покупатель выбирает порядок товаров: сначала новинки или по цене. Выбор должен переживать обновление страницы и шариться ссылкой.

## В зоне спеки

- Допустимые значения сортировки и подписи кнопок.
- Дефолт и запись в URL (`?sort=`).
- Порядок товаров (включая одинаковую цену и битую дату).
- Сортировка применяется **после** поиска и фильтра категорий, состав выборки не меняет.

## Вне зоны

- Поиск и категории (уже есть; сортировка только упорядочивает результат).
- Сортировка на PDP и в корзине.
- Бесплатная доставка.

## Значения

| `sort` | Подпись на витрине | Правило |
| --- | --- | --- |
| `new` | По новизне | `releasedAt` по убыванию |
| `price-asc` | Цена ↑ | `priceCents` по возрастанию |
| `price-desc` | Цена ↓ | `priceCents` по убыванию |

Дефолт: `new`. Других значений нет.

## Сценарии

### 1. Первый заход

**Дано** открыт `/catalog` без `sort`  
**Тогда** активна «По новизне»  
**И** в адресе нет `sort`.

### 2. Выбор и ссылка

**Дано** покупатель нажимает «Цена ↑» или «Цена ↓»  
**Тогда** список перестраивается  
**И** в URL появляется `?sort=price-asc` или `?sort=price-desc`  
**И** поиск (`q`) и категории (`cat`) сохраняются.

**Дано** снова выбрано «По новизне»  
**Тогда** параметр `sort` из URL убирается.

### 3. Некорректный query

**Дано** `?sort=foo`, пустая строка, массив или не строка  
**Тогда** поведение как у дефолта `new`  
**И** неизвестное значение не подсвечивает чужую кнопку.

### 4. Ничья и битая дата

При равном ключе сортировки порядок стабилен: меньший `id` раньше.

Невалидный или пустой `releasedAt` для режима `new` считается старше любого валидного (timestamp `0`) и уходит в конец списка новизны.

### 5. Фильтры

Сортировка не добавляет и не выкидывает товары. Сброс категорий не сбрасывает выбранную сортировку.

## Примеры (источник правды для тестов)

Фикстура (порядок во входе нарочно «ломаный»):

| id | priceCents | releasedAt |
| --- | ---: | --- |
| b | 100 | 2026-01-02 |
| a | 100 | 2026-01-01 |
| d | 200 | 2025-06-01 |
| c | 50 | not-a-date |

### parseCatalogSort

| вход | результат |
| --- | --- |
| `undefined` | `new` |
| `''` | `new` |
| `foo` | `new` |
| `new` | `new` |
| `price-asc` | `price-asc` |
| `price-desc` | `price-desc` |
| `['price-asc', 'new']` | `price-asc` |
| `['nope']` | `new` |

### catalogSortQueryParam

| sort | query |
| --- | --- |
| `new` | `undefined` (не писать в URL) |
| `price-asc` | `price-asc` |
| `price-desc` | `price-desc` |

### sortCatalogProducts — порядок id

| sort | id по порядку |
| --- | --- |
| `new` | `b`, `a`, `d`, `c` |
| `price-asc` | `c`, `a`, `b`, `d` |
| `price-desc` | `d`, `a`, `b`, `c` |

Пояснения:

- `new`: 2026-01-02 (`b`) новее 2026-01-01 (`a`); `d` валиден, но старше; `c` с битой датой последний.
- `price-asc`: 50, затем два по 100 — ничья `a` перед `b` (id), затем 200.
- `price-desc`: 200, затем ничья 100 (`a` перед `b`), затем 50.

Исходный массив не мутируется.
